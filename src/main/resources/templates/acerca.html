Proyecto académico

Acerca de esta plataforma

Pre-evaluación digital de créditos: propuesta de innovación para Caja Piura. Curso de Herramientas de Desarrollo.

Proceso principal

El cliente completa el formulario de pre-evaluación con su ingreso mensual, el monto solicitado y el destino del crédito, y puede adjuntar su DNI y su sustento de ingresos. El sistema calcula el ratio monto solicitado / ingreso mensual: si es menor o igual al límite configurado (4 por defecto), la solicitud queda pre-calificada; si es mayor, requiere revisión. En ambos casos el resultado converge en la evaluación formal de un asesor de negocios, nunca reemplazado por el sistema.

Secuencia del proceso

1. Pre-evaluación
El cliente llena el formulario público y el sistema calcula el resultado preliminar al instante.
2. Asignación automática
La solicitud se reparte entre los asesores activos, equilibrando la carga de trabajo del equipo.
3. Agendamiento o contacto
Si calificó, el cliente agenda su cita; si no, el asesor lo contacta con alternativas.
4. Seguimiento colaborativo
El equipo de asesores da seguimiento desde el tablero Kanban, deja comentarios internos y el sistema registra cada cambio de estado.
5. Evaluación formal
Un asesor de negocios realiza la evaluación final del crédito y cierra el expediente.

Herramientas de colaboración de equipo

Varios asesores pueden trabajar en paralelo con sus propias cuentas. Cada solicitud se asigna automáticamente al asesor con menos carga activa, y el equipo puede dejar comentarios internos con autor y fecha sobre cada caso, visibles para todos en el panel.

Herramientas de gestión de actividades

El panel incluye un tablero Kanban (arrastrar y soltar) con las columnas Pendiente, Cita agendada, En revisión, Contactado y Cerrado, además de un dashboard de analítica con la tendencia de solicitudes, la distribución por destino de crédito y la tasa de pre-calificación.

Stack técnico

Backend: Spring Boot 3 (Java 21), Spring MVC, Spring Data JPA, Spring Security
Vistas: Thymeleaf + CSS propio
Base de datos: H2 (archivo local)
Reportes: generación de PDF con OpenPDF
Gráficos: Chart.js
Control de versiones: Git / GitHub, con ramas main, develop y feature/*
CI: GitHub Actions (build y pruebas automáticas)
Despliegue: Docker + Render
